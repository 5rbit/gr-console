# UI/UX 개선 — 리서치와 결정 기록

`docs/DESIGN.md`가 **지금의 규칙**이고, 이 문서는 **왜 그 규칙이 됐나**다. 규칙을 바꿀 때 여기에
줄을 더한다(지우지 않는다 — 버린 선택지의 이유가 다음 사람의 시간을 아낀다).

- 대상: `apps/gr-web` 셸
- 요구: ① 다기종 로봇 제어기 + 개발 툴에 맞는 셸, **창을 사용자가 자유롭게 구성** ② 간단하고 일관된
  사용성, **데이터 위주의 뷰** ③ 작업 도구(유니티 · VSCode) 리서치 후 적용

---

## 1. 무엇이 문제였나

개선 전 셸은 **메뉴바 + 고정 왼쪽 사이드바 + 화면 하나 + 상태바**였고, 화면 넷(작업 명령 · Task
관리 · 측정 모니터 · 시나리오)을 탭으로 갈아 끼웠다.

1. **왕복이 전부 탭 전환이다.** 명령을 내고 결과를 보려면 `작업 명령` → `Task 관리`로 화면을 떠나야
   하고, 돌아오면 작성 중이던 맥락이 사라진다. 엔지니어링 콘솔의 실제 일은 명령 → 결과 → 값의
   **왕복**인데 셸이 그 왕복을 화면 전환으로 만들었다.
2. **보조 면을 옮길 수 없다.** 로봇·PLC·상태 세 목록이 `Sidebar.tsx` 안에 코드째 박혀 있어 오른쪽에
   붙이거나 접거나 하단으로 내릴 수 없었다. 벽 모니터와 노트북이 같은 배치를 강요받는다.
3. **일관성의 축이 화면마다 갈렸다.** 밀도 스위치가 사이드바 안에만 있었다(`gr-sidebar-dense`) —
   "좁게 보기"가 사이드바에만 적용되고 표에는 적용되지 않는다.
4. **규칙이 문서가 아니라 주석에 흩어져 있었다.** `CLAUDE.md`도 스킬도 없어서, 화면별 담당
   에이전트가 각자 다른 규칙으로 UI를 늘렸다. → 그래서 이번 작업의 1번 산출물이 `docs/DESIGN.md`다.

## 2. 리서치 — 유니티 · VSCode

### 가져온 것

| 출처 | 가져온 것 | 왜 |
| --- | --- | --- |
| VSCode `Part` 격자(사이드바·패널·에디터 그룹을 Layout이 배치) | 존 넷(왼쪽·중앙·오른쪽·하단) 도킹 | 명령·결과·값이 한 화면에 선다 |

| Unity 도킹 창의 창 메뉴(maximize·close 등) | 탭 우클릭 / `⋮` 메뉴 | 드래그를 못 쓰는 환경(터치 모니터·장갑)의 유일한 이동 수단 |
| Unity UX Essentials — 빈 창 대신 빈 상태, 비활성 컨트롤은 **이유**를 말한다, 조작 라벨은 동사 | `EmptyState`·`disabled` 사유·라벨 규칙 | 기존 규칙(조작/표시 분리)과 같은 방향이라 바로 얹혔다 |
| Unity 최소 폭 강제(Inspector 275px) | `ZONE_LIMITS`의 존별 min/max | 줄일 수 있는 폭에는 **읽을 수 없는 폭**이 포함되면 안 된다 |

### 버린 것 — 그리고 그 이유

| 버린 것 | 이유 |
| --- | --- |
| **OS 창으로 떼기(pop-out)** — 유니티·VSCode의 Floating Window | 단일 PLC 문맥이라 떼어 낼 만큼 독립적인 창이 없다. 벽 모니터에서 떼어 낸 창은 유실된다. 브라우저에서는 별 window라 스토어·SSE가 갈리고, **값이 두 창에서 다르게 보이는 것**이 이 콘솔에서 가장 나쁜 버그다 |
| **자유 좌표 플로팅** | 겹친 창은 가려진 값을 만들고, 가려진 값은 없는 값보다 나쁘다 |
| **중앙 좌우 분할(에디터 그룹 여러 개)** | 지금은 하단 존이 그 일을 한다. 넣기 전에 "무엇을 나란히 보는가"의 실사용 예가 필요하다(백로그) |
| **Zen 모드** | 최대화(`Alt+Enter`)가 같은 필요를 채우고, 상태바를 숨기는 것은 이 콘솔에서 위험하다(알람이 상태바에 있다) |
| **탭 고정(Pin)** | 탭이 패널당 하나뿐(최대 일곱)이라 고정으로 아낄 것이 없다 |
| **다중 창 레이아웃을 서버에 저장** | 배치는 "그 사람 그 모니터"의 성질이다. 같은 계정이 24인치와 벽 모니터를 오가며 같은 배치를 강요받으면 매번 다시 짠다 → localStorage + 이름 붙인 저장 |

### 설계 결정 몇 가지 (왜 그렇게)

- **불변식을 `normalize()` 하나로.** 레이아웃을 바꾸는 길이 넷(드래그·프리셋·복원·팔레트)이라, 규칙을
  각 경로에 두면 한 곳만 빠뜨려도 "탭은 있는데 아무것도 안 그려지는" 화면이 난다.
- **`lib/workspace`는 패널 id만 안다.** lib이 화면을 import하면 순수 모델 테스트가 React를 끌고 온다.
  경계는 `components/workspace/paneRegistry.tsx`.
- **비활성 탭 언마운트.** 화면 넷이 동시에 살면 SSE·폴이 넷 다 돈다. `renderedPanes()`가 그 규칙을
  계산하고, 최대화도 "존 하나만 그린다"로 구현했다(`display:none`이 아니라).
- **머리띠 요약을 컴포넌트로 export.** 함수로 내면 껍데기가 그 스토어를 구독하지 않아 숫자가 굳는다.
- **`nav.tab` ↔ 중앙 활성 탭 양방향 동기화.** 다른 화면의 `nav.goTask(id)`가 도킹 모드에서도 그
  패널을 드러내야 하고(숨은 탭이면 눌러도 아무 일도 없는 것처럼 보인다), 사용자가 중앙 탭을 바꾸면
  `?tab=` 딥링크가 따라와야 한다. 서로를 다시 부르지 않도록 **마지막으로 본 값**으로 누가 먼저
  움직였는지를 가른다(`WorkspaceShell`).
- **밀도는 CSS 변수로.** 컨트롤 높이 토큰만 갈아 끼우고 킷이 그 토큰으로 높이를 부르게 했다 —
  그러면 화면은 손대지 않아도 따라온다(그 대가로 킷의 하드코드 높이를 한 번 걷어 냈다. 아래
  '가이드로 대조하면서 찾은 것' 2번). 글자 크기는 건드리지 않는다(11px 아래는 오독).

### 가이드로 대조하면서 찾은 것 둘

`docs/DESIGN.md`를 먼저 쓰고 그 규칙으로 이번 코드를 훑었더니 **문서가 코드의 거짓말을 두 개
잡았다**. 이것이 가이드를 먼저 쓴 값이다.

1. **좁은 존에서 `ScreenHeader`가 글자 중간에서 끊겼다.** 화면이 도킹 존(오른쪽 200~560px)에 들어갈
   수 있게 되면서 요약 항목이 줄바꿈되며 `실 행 0`이 됐다. 끊긴 값은 안 보이는 값보다 나쁘다 —
   읽을 수 있다고 착각하게 만든다. → 컨테이너 쿼리로 32rem 미만이면 요약을 접는다(제목·조작이 먼저).
   미디어 쿼리가 아닌 이유: 기준이 창 폭이 아니라 **그 띠가 든 존의 폭**이다.
2. **밀도의 실제 효력이 문서가 주장한 것보다 훨씬 작았다.** 컨트롤 높이 토큰을 쓰는 자리가 셋뿐이고
   `h-7`/`h-8`/`h-9` 하드코드가 33곳이었다 — 밀도를 켜도 킷 절반이 제 높이로 남아 줄이 어긋났다.
   → 킷의 높이를 토큰으로 바꿨다(`Button`·`Input`·`Select`·`Switch`·`Segmented`·`IconPopover`·
   `ScreenHeader`·`Toolbar` + 셸 메뉴바·탭 띠). 측정: 메뉴바 36→30 · 머리띠 36→30 · 컨트롤 32→28 ·
   상태바 24→24(일부러 안 줄인다). 문서를 코드에 맞춰 낮추는 대신 **코드를 문서에 맞춰 올렸다**.

### UX 전반 점검 — 평가와 고친 것

실제 앱을 브라우저로 몰아 보며 셸을 평가했다. 나온 문제 여섯과 처리:

| # | 평가 | 고친 것 |
| --- | --- | --- |
| 1 | **제목이 두 번 나왔다** — 탭이 `Task 관리`를 말하고 그 아래 머리띠가 또 말했다. 30px을 정보 없이 먹는다 | 껍데기가 문맥으로 "이름은 내가 말했다"를 선언하고 `ScreenHeader`가 제목을 접는다(`lib/ui/paneChrome.ts`). 요약·조작만 남고, 남을 것이 없으면 띠 자체가 사라진다. 화면 코드는 손대지 않았다 |
| 2 | **창 경계가 안 보였다** — 스플리터가 hover 전에는 투명해서 "끌 수 있다"도, 면이 갈리는 자리도 화면에 없었다 | 선을 항상 1px로 보이게 하고 hover에서 3px·초록으로. 경계가 곧 크기 손잡이라는 것이 보인다 |
| 3 | **어느 패널이 활성인지 몰랐다** — `Alt+Enter`가 늘 중앙을 최대화했다. 오른쪽을 보다 눌러도 중앙이 커진다 | `workspace.focused`(마지막으로 만진 패널)를 도입. 창 명령의 대상이 되고, 활성 존의 탭 띠가 밝아지고 그 탭만 accent 밑줄을 받는다(다른 존은 회색 밑줄) |
| 4 | **빈 존이 사라져 도킹의 막다른 길이 생겼다** — 패널이 하나도 없는 존은 화면에서 없어져서, 탭을 끌어도 놓을 자리가 없었다(창 메뉴만이 길) | 드래그 중에는 빈 존도 점선 레일로 뜬다. 놓을 수 있는 자리는 끌고 있는 동안 보인다 |
| 5 | **토글 관용구가 갈렸다** — 메뉴는 체크박스, 팔레트는 `접기`/`펼치기`로 라벨이 뒤집혔다 | 팔레트도 체크로 통일(`왼쪽 존` + 체크). 같은 항목을 두 이름으로 배우지 않는다 |
| 6 | **닫기(✕)가 hover에만 있었고, 닫힐 수 없는 탭에도 있었다** | 활성 탭의 ✕는 늘 보인다(hover-only는 없는 기능이다). 중앙의 마지막 탭에는 ✕를 그리지 않는다 — 눌러도 아무 일 없는 버튼은 고장으로 읽힌다. 최대화 중에는 탭 띠에 `해제` 버튼이 선다(나가는 길은 화면에) |

### 좁은 폭의 표 — 열 우선순위 (2차)

머리띠는 접었지만 표는 여전히 가로 스크롤이었다. 리서치에서 고른 답은 **열 우선순위 + priority+**다:
낮은 숫자가 오래 남고(DataTables의 `responsivePriority` 관례), 접힌 열은 **행을 펼치면** 라벨+값
짝으로 돌아온다. 전략 셋 중에서 고른 이유:

| 전략 | 언제 맞나 | 이 콘솔에서 |
| --- | --- | --- |
| 가로 스크롤(+첫 열 고정) | 데이터 **무결성**이 중요할 때 | **고치는 표**(`DataGrid`)가 이것이다 — 편집 격자에서 열을 숨기면 편집 가능한 값이 조용히 사라지고 붙여넣기 대상이 화면과 달라진다 |
| 카드로 바꾸기 | 행이 적고 하나씩 읽을 때 | 안 쓴다. 이 콘솔의 표는 **훑는** 표다(카드는 훑을 수 없다) |
| 우선순위 접기 + 행 펼치기 | 우선순위가 분명할 때 | **읽는 표**(`DataTable`) 전부가 이것 |

기준은 창 폭이 아니라 **표가 든 컨테이너 폭**이다(존 하나가 273px일 수 있다). 판정은 순수 함수
(`lib/ui/table.ts`)가 하고 테스트 9건이 못 박는다. 우선순위는 옵트인이라(기본 1) 안 적은 표는
동작이 그대로다. 적용: Task 목록 · 종결 이력 · 측정 이력 · 시나리오 목록.

측정(1600×900, 데모 데이터): 오른쪽 존 273px → 열 3 + 펼치기, 최대화 1574px → 열 12,
펼치면 접힌 9열이 라벨+값으로.

### 구현하며 잡은 버그 둘 (스크린샷만으로는 못 잡았다)

1. **창 메뉴(`⋮`)가 한 번도 열리지 않았다.** `ContextMenuHost`는 바깥 클릭을 window에서 듣는데,
   버튼을 누른 그 클릭이 계속 올라가 **열자마자 닫았다**. 우클릭 경로는 `ctxMenu.show`가 이벤트를
   멈춰서 멀쩡했고, 그래서 버튼에서만 났다. 스크린샷 파일명(`28_window_menu`)을 보고 "확인됨"으로
   넘긴 것이 잘못이었다 — 지금은 **메뉴 항목 수를 세는 검증**이 있다(5개).
2. **뒤늦게 마운트된 표는 폭을 영원히 몰랐다.** `useElementWidth`가 마운트 때 한 번만 관찰해서,
   로딩·빈 상태를 거쳐 행이 도착한 뒤 마운트된 표는 `width`가 `null`로 남아 열이 하나도 접히지
   않았다(종결 이력이 그랬다). 요소를 **상태로** 들어 생기는 순간 다시 관찰한다.

교훈: 화면 검증은 **숫자로 단정**해야 한다. "스크린샷을 찍었다"는 "동작한다"가 아니다.

### 자리와 절제 — 새로 만든 기준

"디자인 요소가 들어갈 자리를 제한하고 절제미가 있어야 한다"는 요구로 `DESIGN.md` 5절을 만들었다.
두 장치다.

- **자리 표** — 메뉴바·탭 띠·머리띠·도구 띠·표·인스펙터·상태바·오버레이·빈 영역 아홉 자리에
  **서는 것과 서지 않는 것**을 적었다. 새 요소가 어느 줄인지 말할 수 없으면 자리가 없는 것이고,
  억지로 끼우지 말고 표에 줄을 먼저 추가한다.
- **절제 예산** — accent는 화면당 주 조작 하나, 아이콘은 컨트롤당 하나, 그림자는 겹칠 때만,
  2px 이상 보더는 활성·선택·위험 전용, 배경 면 4층, 글자 크기 화면당 셋, 굵기 700 금지, 모션은
  색 전환과 값 플래시뿐. 아예 안 쓰는 것(그라디언트·블러·일러스트·이모지)도 적었다.
  예산이 있으면 새 요소를 넣을 때 **무엇을 뺄까**를 먼저 묻게 된다.

근거는 취향이 아니다: 이 화면에서 **값이 알람**이라, 장식이 늘면 "방금 무엇이 바뀌었나"가 장식과
경쟁한다. 전이 상태(드래그 점선·리사이즈 초록·값 플래시)는 손을 떼면 사라지므로 예산 밖이다.

*자기 감사에서 걸린 것*: 내가 만든 탭 띠가 `bg-slate-200/70`처럼 **투명도로 배경 면 5층**을 만들고
있었다(예산: 4층). 스케일 값으로 고정했다. 남은 편차: `StatusBar`의 `bg-slate-100/70`은 이 변경
전부터 있던 것이라 손대지 않았다(아래 백로그).

### 남은 표들의 우선순위 (3차)

`DataTable`을 쓰는 표 전부에 우선순위를 매겼다 — 각 표의 기준을 코드 주석에 한 줄로 남겼다
("이 표를 무엇 때문에 훑는가"가 곧 우선순위 1이다).

| 표 | 1(항상) | 2 | 3 |
| --- | --- | --- | --- |
| 셀 레지스트리 | Id · 상태 | 구역 · 행 · 열 · 사용 | 블렌드 · 좌표 · 치수 |
| 스테이션 레지스트리 | Id · 상태 | 작업 · 컨베이어 · 사용 | 그룹 · 회전 · 연결 · 구역 · 좌표 · IO · 센서 |
| 품목 레지스트리 | 코드 · 이름 | 수량 · 내경 · 높이 | 외경 · 비드 · 처짐 · 비고 |
| 재고 | 셀 · 수량 | 품목 · 갱신 | 좌표 · 높이 · 출처 |
| PLC Task(측정) | Work · Task | 종류 · Cell · Code | 단 · 치수 · 좌표 · 플래그 |
| 시나리오 실행 이력 | 시나리오 · 상태 · 오류 | 시작 · 회차 | 결과 건수 |

**일부러 손대지 않은 표 셋**:
- 열이 **다섯 이하**인 표(레지스트리 diff `Id/상태/로컬/PLC`, 가져오기 오류 `행/시트/문제`,
  시나리오 결과 `회차/스텝/상태/Task`) — 접을 것이 없다. 우선순위는 열이 다섯을 넘을 때의 도구다.
- `PlanCard`의 순차 계획 표 — `DataTable`이 아닌 **편집 표**다(수량·Z를 그 자리에서 고친다).
  편집 표는 접지 않고 스크롤한다(같은 이유로 `DataGrid`도 제외했다).

검증(데모 백엔드): 스테이션 표가 창 1600px에서 열 14 → 창 700px에서 **열 2 + 펼치기**.
Task 표 12 → 3, 종결 이력 10 → 3. 시나리오 이력은 실행 기록이 있어야 뜨므로 단위 테스트로만 덮었다.

### 디자인 시스템을 기계가 강제하게 (4차)

"토큰으로 하드코딩 못하게 하고 디자인 시스템을 강요하도록" — 문서만으로는 안 지켜진다는 증거가 이미
이 저장소에 있었다(토큰을 쓰라는 주석 옆에서 `h-8` 하드코드 33곳, 그래서 밀도가 반만 작동). 그래서
린터를 만들고 `npm run check`에 넣었다(이 저장소에는 CI가 없어 강제할 자리가 거기 하나다).

- `apps/gr-web/tools/design-lint.mjs` — 의존성 없는 node 스크립트. 규칙 여섯: `no-raw-color` ·
  `no-opacity-surface` · `no-arbitrary-value` · `no-control-height`(킷·셸만) · `no-font-bold` ·
  `no-decoration`(그라디언트·블러·이모지).
- **기준선 방식** — 파일×규칙별 현재 개수를 `design-lint.baseline.json`에 박고 **늘어나면 exit 1**.
  기존 위반 169건을 한 번에 고치는 것은 한 변경의 범위가 아니지만, 미루면 새 코드가 계속 늘어난다.
  줄이면 기준선을 낮추라고 알려 준다(한 번 고친 자리는 되돌아갈 수 없다).
- **예외는 이유와 함께** — `// design-lint-allow: <규칙> — 이유`. 이유(`—`)가 없으면 통과하지 않는다.
- 위반 메시지는 규칙 이름이 아니라 **무엇이 깨지는지**를 말한다("스타일 위반"은 아무것도 안 가르친다).

만들면서 두 가지를 배웠다.
1. **린터가 자기 문서를 잡았다.** `app.css`의 "글자 표식(★·NEW)은 쓰지 않는다"라는 규칙 설명이
   이모지 규칙에, `"PICK 셀#101"` 예시가 색값 규칙에 걸렸다 → 주석을 벗겨 내고 검사한다.
2. **막는지 직접 시험했다.** 일부러 위반 넷(색값·임의값·굵기·투명도 면)을 넣어 exit 1과 메시지를
   확인하고 되돌렸다. "린터를 만들었다"는 "막는다"가 아니다.

린터가 잡은 진짜 위반 둘도 고쳤다: 모달·확인 대화상자 백드롭의 `backdrop-blur-sm`(예산: 블러 없음).

린터가 **못 보는 것**은 체크리스트가 본다 — 자리 표, accent 하나 예산, 아이콘 개수, 그림자를
겹치는 면에만 썼는지.

### 기준선 갚기 (5차) — 169 → 11

린터를 켠 뒤 빚을 갚았다. **두 종류의 일이 섞여 있었다**: 진짜 하드코드와 **규칙이 과녁을 잘못 잡은 것**.

**갚은 것(진짜 하드코드)**
- 글자 크기 임의값 88건 → 토큰(`text-[11px]`→`text-2xs`, `text-[10px]`→`text-3xs`,
  `text-[13px]`→`text-sm-tight`). `text-[9px]` 5건은 스케일에 없는 크기라 `text-3xs`(10px)로 올렸다.
- `rounded-[2px]`→`rounded-mark`, `min-h-[240px]`→`min-h-60`.
- 스플리터 기하(`w-[7px]`·`h-[3px]`·`left-[3px]`·`mx-[3px]` …) → `app.css`의 `.ds-splitter*`
  유틸리티로 **모았다**. 임의값을 컴포넌트에 뿌리면 손잡이를 손볼 때마다 여러 곳을 고쳐야 한다.
  컴포넌트는 동작(포인터·키보드·값 계산)만 남았다. 드래그 220→300px, 키보드 300→284px로 확인.
- 중립색 면의 투명도 5곳 → 스케일 값(`StatusBar` · `Card` · `DataTable` 상세 행 · `DataGrid`
  줄무늬·hover · `IconPopover`). 특히 맵 위에 떠 있는 아이콘 버튼(`bg-white/95`)은 **불투명**해야
  아래 그림에 글자가 섞이지 않는다.

**규칙을 좁힌 것(린터 품질)**
- `no-arbitrary-value`: 폭·높이·위치·z·shadow를 과녁에서 뺐다. 남은 것이 `w-[620px]`(대화상자) ·
  `max-h-[70vh]` · `max-w-[calc(100%-6rem)]`처럼 **스케일이 있을 수 없는 값**이었고, 그것까지 막으면
  가짜 토큰이 생기거나 예외 주석이 스물이 된다. 예외가 스물인 린터는 아무도 켜 두지 않는다.
- `no-opacity-surface`: 중립색(white·slate·neutral·gray)만 본다. 46건 중 대부분이
  `dark:bg-amber-500/15` 같은 **상태 soft 틴트**였는데 그건 면이 아니라 라이트의 `bg-amber-50`에
  대응하는 다크 값이다. 다크 soft 토큰이 없다는 사실은 `DESIGN.md` 6절이 이미 절충으로 적어 뒀고,
  린터가 그걸 매일 다시 보고할 이유가 없다.
- 예외 주석 판정이 **한 줄 위만** 봐서, 이유를 두 줄로 적으면 예외가 먹지 않았다(실제로 놓쳤다) →
  위로 **주석인 줄만 세 줄까지** 훑는다(코드 줄을 만나면 멈춘다).

**남은 11건**은 전부 화면 안이다: `CellMap` 7(축 표시용 적·녹 색값 4 + 9px 범례에서 온 `font-bold`
3) · `ByCode`·`LayoutTab`·`PlanCard` 각 1(맵/표 위 반투명 오버레이). 앞의 것은 도메인 색(X=적,
Y=녹)이라 `--color-fault`/`--color-ok`로 바꾸거나 이유를 적으면 되고, 뒤의 것은 아래 내용을 보여
주려는 **의도된 반투명**이다 — 둘 다 그 화면 담당의 판단이 맞아서 기준선에 남겼다.

### 다크 토큰 (6차) — "기본은 화이트톤"을 지키면서

4번 백로그("다크를 제대로 지원하거나 버린다")를 닫았다. **지원**으로 결정했고, 방식은 토큰 한 층이다.

- `tokens.css`에 `:root[data-theme='dark']` 한 블록 — **시맨틱 토큰만** 다시 정의한다. 라이트는 위
  `@theme`에 그대로 남아 기본이다. 원시 스케일은 건드리지 않는다.
- `lib/ui/status.ts`(상태 6종 단일 진실원)를 토큰 클래스로 바꿨다: `bg-emerald-50
  dark:bg-emerald-500/15` → `bg-ok-soft`. 배지·점을 쓰는 모든 화면이 한 번에 따라온다.
- 킷(`lib/ui/**`)과 셸 전체를 시맨틱 토큰으로 옮겼다 — `dark:` 짝 **173개 제거**, 원시 색 클래스
  **255개 치환**. 킷·셸의 `dark:`는 이제 0개다.
- 그 상태를 린터가 잠근다: `no-dark-variant` · `no-raw-palette`(킷·셸 범위).

**값은 대비 계산으로 골랐다.** 눈대중으로 다크를 만들면 야간에 값을 잘못 읽는다. 글자
16.0/12.9/6.2 · 채운 accent 위 흰 글자 4.6 · 글자용 accent 6.5 · 상태 fg↔soft 5.5~7.5 ·
soft↔panel 1.25~1.73. soft에 950 틴트를 쓰면 panel과 1.0~1.1이라 **배지가 모양으로 사라진다** —
그래서 900 틴트다.

**토큰 세트에서 빠져 있던 것 셋을 찾았다** (코드가 원시 스케일을 부르고 있던 자리):
- `surface-active`가 `inset`과 같은 `#ebebe8`이었다 → 눌린·선택된 면을 그릴 토큰이 없어서 화면이
  `slate-200`을 불렀다. `#dededa`로 정정(inset보다 한 단계 짙게).
- 글자 층이 다섯 중 셋만 있었다 → `content-tertiary`(#5a5a53) · `content-disabled`(#c6c6c1) 추가.

### 라이트가 움직이지 않았다는 것을 어떻게 확인했나

기본이 화이트톤이니 **라이트 픽셀이 변하지 않아야** 한다. 그래서 변환 전 스크린샷 넷을 떠 두고
매 단계 픽셀을 셌다(의존성 없이 PNG를 디코드하는 스크립트). 데모 데이터가 흐르므로 **노이즈 바닥**
(같은 빌드 두 번: 0.03~0.09%)을 먼저 재고 그것과 비교했다.

결과: 2.37% → 0.10% → **0.15~0.64%**(남은 것은 전부 설명된다).
- `#008742 → #006b35` — `bg-indigo-600`을 쓰던 채운 버튼이 토큰 `bg-accent`가 됐다. 토큰이 700을
  쓰는 이유가 바로 대비(흰 글자 4.6 → 6.7)라, 이것은 **의도된 정렬**이다.
- `d-menu` 4.27% — 보기 메뉴가 넓어졌다(아래 버그 수정).

### 이 과정에서 잡은 것 셋

1. **다크에서 버튼 글자가 사라졌다** — `text-slate-800`이 매핑 표에 없어서 `dark:text-slate-100`만
   지워졌고, 다크 면(#2c2c27) 위에 #2c2c27 글자가 남았다. 캡처를 눈으로 보고 발견했다.
2. 그 종류를 다시 놓치지 않으려고 **기계 검사**를 붙였다: 두 테마에서 잎 노드의 글자색↔배경색 대비를
   전부 재서 2.0 미만을 보고한다. 지금 라이트 1건(빈 값 표식 `—`, 의도) · 다크 0건.
3. **보기 메뉴가 글자마다 끊겼다**(`명령 중 / 심`) — 라벨이 `flex-1`이라 긴 힌트에 밀렸다.
   4절 ②가 금지하는 그 증상을 메뉴가 하고 있었다 → 라벨은 줄어들지 않고 힌트가 먼저 잘린다.

한 가지 더: 2차 변환 스크립트가 `text-slate-300`/`400`을 **개수로만** 되돌려 위치가 어긋났다
(`text-slate-400`이 한 단계 밝은 `content-disabled`가 돼 대비 1.44가 됐다). 원본과 순서를 맞춰
다시 매핑해 6곳을 바로잡았다 — 기계 검사가 그것을 잡았다.

### 화면 넷도 토큰으로 (7차) — 기준선 11 → 0

6차가 남긴 일감(4·5번 백로그)을 닫았다. `components/{task,taskmgr,measure,scenario,shared}` 전부를
한 판에 옮겼다: `dark:` 짝 **153개 제거**, 원시 색 클래스 **268개 치환**. `CellMap`의 SVG
`stroke="#dc2626"`는 `var(--color-fault)`로, `fontWeight 700`은 600으로. 남은 것은 맵 데이터의
색상환(품목별 hue)뿐이고 그것은 색표가 아니라 **데이터**라 그대로다.

- 상태 여섯 밖의 색이 딱 하나 있었다 — `cellTone('pending-restart')`의 **보라**(재시작해야 반영되는
  값은 나쁜 상태가 아니라 시간축 표식). 원시 `violet-*` 대신 `--color-pending-fg/soft` 토큰 짝을
  두 테마에 넣었다. 측정 이력의 종류 색(`KIND_TONE`)과 JSON 뷰의 값 종류 색(`VAL_CLASS`)도
  `text-teal-600`·`text-emerald-700` 같은 원시 스케일을 상태 fg 토큰으로 바꿨다 — **뜻**(ok·warn)이
  아니라 **구분**으로 쓰는 것이라 dot이 아닌 fg만 빌린다.
- 그래서 `no-dark-variant`·`no-raw-palette`의 `only:` 범위를 풀어 **프런트 전체**에 걸었고 기준선을
  다시 적었다: **0건**. 이제 기준선 파일은 `{}`다 — 새 위반은 하나라도 `npm run check`를 떨어뜨린다.
- 확인: 라이트 픽셀 차이 0.01~0.05%(노이즈 바닥 안), 작업 명령 1.67%는 localStorage에 남은 맵
  줌(1000→500mm)이지 색이 아니다. 대비 2.0 미만은 다크 네 화면 0건, 라이트는 예전 그대로 의도된
  `—` 1건. 다크 네 화면은 `screenshots/44~47`.

### 캡슐은 자리가 고정된 곳에만 (8차)

지적: "캡슐(뱃지)은 꼭 필요한 곳에만. 위치가 고정되지 않아 가독성을 떨어뜨린다." 맞다 — 캡슐은
글자 길이대로 폭이 바뀌고 앞 글자에 얹혀 흐르므로 **행마다 다른 x**에 색 덩어리가 선다. 세로로
훑는 눈은 자리가 맞는 것만 비교한다. 전수 조사에서 `StatusBadge` 23곳 중 자리가 고정된 곳(표의 상태
열 · 상세 머리줄)은 8곳뿐이었다.

- **규칙**(DESIGN.md 4절 ④ · 5절 자리 표·예산 · 10절 체크리스트): 캡슐은 ① 표의 상태 열(한 표에
  하나) ② 상세 머리줄(하나)에만. 그 밖(이름 옆 · 값 자리 · 비트 묶음 · 개수)은 **점+글자**
  (`StatusDot` + label). 점은 폭이 고정이고 라벨 앞에 서니 열이 맞는다. 정상(ok) 캡슐은 그리지
  않는다. 캡슐 라운딩은 4px — 알약(`rounded-full`)은 점의 모양이라 글자를 담는 면에 쓰지 않는다.
- **옮긴 것 15곳**: 로봇 행의 `선택`(면이 이미 말한다 → 삭제) · PLC 행의 `레이아웃 OK`(정상은 침묵,
  고정폭 자리에 이상 시 점만) · 사이드바 개수 알약(숫자) · Task 표의 `PLC와 불일치`(점 하나) ·
  Task 상세의 불일치·이력(고정폭 열의 점+글자) · 시나리오 목록의 `실행 중`(이름 **앞** 고정 자리의
  점) · 회차 값(점+글자) · 측정 대시보드의 비트 칩 구름 13+6+8+4+4개 → **고정 격자**
  (`.ds-bitgrid`, 점+이름, 꺼진 비트도 같은 자리에 흐리게) · 알람 코드(색 글자 나열) · Fault/Warn
  `ON`(점) · 셀/스테이션 레지스트리의 `PLC 동일`(흐린 글자) · 차이 대화상자의 `동일`·범례(점+글자) ·
  Task 필터 칩(조작이라 `rounded`).
- **린터 `no-pill`**: 같은 줄에 `rounded-full`과 `px-`가 함께 있으면 글자를 담는 알약이다. 기준선 0.
- 꺼진 비트를 속 빈 사각형으로 그렸다가 되돌렸다 — 빈 사각형은 체크박스로 읽힌다(`StatusDot`의
  실측 기록). 중립 채움이 맞다.

### Task 목록의 행 액션 (9차)

요청: 목록에서 바로 취소·완료. `DataTable`에 있던 `actions` 열을 켜고 `TaskActions`를 `only=['cancel',
